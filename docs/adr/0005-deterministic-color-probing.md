# decision-5: 色割当は決定的プロービングで生成し HRE 領邦は独立色化する

> **追補:** [decision-32](0032-colors-snapshot-additive.md) により、
> 本 ADR の「独立勢力は全色 distinct」という保証は「同年内一意」へ緩和された。
> パレット飽和（288 スロット中 287 使用済み）が Issue #193 で確認されたためで、
> `colors.json` はスナップショット正、`build-colors` は既存色を保持して新規キーだけを
> 割り当てる差分追加モードになった。本 ADR の Decision は当時の決定として保持する。

## Context

勢力ごとの塗り色は、年代を跨いで同一勢力が同色になるよう決定的に割り当てる必要がある。単純なハッシュ % パレット数では誕生日衝突により独立勢力 256 中 150 が同色になった（TASK-3 レビューで発覚）。また HRE 領邦は当初「宗主国色の明度シフト」だったため全領邦がほぼ同色になり識別できなかった（TASK-19）。

## Decision

色割当はビルド時静的生成（scripts/build-colors.ts → data/colors.json）とし、FNV-1a ハッシュ起点 + ソート順の線形プロービングで衝突を決定的に解決する。パレットは色相 24 段（黄金角）× 彩度 3 段 × 明度 4 段 = 288 色。SUBJECTO を持つ属領は宗主国色相の明度違いとするが、宗主国が Holy Roman Empire の領邦のみ例外として NAME ベースの独立プロービング色を割り当てる。

## Consequences

- 同一勢力は全年代で同色・独立勢力は全色 distinct が保証され、クライアントは colors.json の参照のみで済む。
- HRE 領邦が個別色で識別可能になる一方、属領の「宗主国と似た色」の原則に例外が生じる。
- パレットへの勢力追加・削除時はプロービング連鎖のずれで既存キーの色が変わりうる（決定性・全色相異は維持）。
- 関連タスク: TASK-3, TASK-19

## decision-32 との関係

`docs/development-style.md` 2.1 章の分類では、全キー一意という条件の緩和と
再生成方式の変更は「決定そのものが変わる」に当たる。その変更は新しい ADR である
[decision-32](0032-colors-snapshot-additive.md) に追補として記録済みである。

本 ADR は `accepted` のままとする。decision-32 は FNV-1a、線形プロービング、
パレット構成、HRE 領邦の独立色化を維持し、保証の範囲と `colors.json` の管理・
更新方式だけを変更しているため、決定全体の置き換えではなく一部追補と判断した。
却下した案は本 ADR を `superseded` にすることである。この状態は色割当方式まで
失効したとの誤解を招き、現在も有効な本 ADR の決定を一覧から判別しにくくするため
採用しない。
