# decision-38: TASK-72 が禁じたのは「明るい不透明パネル」であり、政治ラベルは濃色・半透明・文字列単位のプレートで地色から分離する

## Context

Issue #333 は「修正 issue を何度積んでも参考画像のような国名ラベルにならない」
という差し戻しである。#228 で導入された参考画像（案A、
`docs/images/issue333-label-reference/reference-plan-a.png`）を規範として、
#267 → #308 → #322 と 3 回にわたり政治ラベルを調整したが、いずれも参考画像に
到達しなかった。

3 回の共通点は、**分離を外縁（SDF halo）の太さだけで作ろうとしていた**ことに
ある。#267 は明色文字 + 暗色外縁、#308 は `outlineWidth` を 9 へ、#322 は 12 へ
と太らせ、合格基準もそれぞれ「1.2px 以上」「#308 の 1.3 倍」「1.6〜2.6px」と
**参考画像との一致ではなく前回からの増分**で定義していた。

参考画像を実測した結果（`docs/research/issue-333-label-reference-targets.md`）、
規範の構成は次のとおりだった。

| 要素           | 参考画像                                                 | #322 本番相当                            |
| -------------- | -------------------------------------------------------- | ---------------------------------------- |
| 文字           | 純白                                                     | クリーム #f8f2e2                         |
| 濃色外縁       | **1.0〜1.5 CSS px**（サイズによらずほぼ一定）            | 12px で 1.69 / 18px で 2.53 CSS px       |
| 文字列の下支え | **角丸の濃色プレート**（alpha ≈ 0.22 + クリーム 1px 縁） | **無し**（alpha 1 の不可視クアッドのみ） |

つまり参考画像は外縁を**細く**保ち、地色からの分離をプレートに担わせていた。
#322 はその逆に、参考画像の 1.5〜1.8 倍の外縁で「参考画像には有るプレート」の
役目まで負わせようとしていた。外縁だけで分離しようとすると 12px ラベルの
カウンターが潰れる（#322 自身が実測した `outlineWidth` 13〜14 の上限）ため、
**この方向では原理的に到達できない**。

到達できなかった真因は測定値ではなく制約の解釈にある。TASK-72
（`docs/archive/backlog-tasks/task-72 - 地図ラベルの背景パネル（白枠）を撤去し白-halo-を実効化する.md`）
が「背景パネルを撤去する」と決めて以降、後続タスクは**あらゆるプレートが
禁じられている**と読み、外縁を太らせる以外の選択肢を検討しなかった。

## Decision

**TASK-72 が禁じたのは「明るい不透明パネル」であり、濃色・半透明・文字列単位の
プレートはその趣旨に反しない。政治ラベルは細い外縁 + このプレートで地色から
分離する。**

TASK-72 の記録を読むと、撤去対象と理由は次のとおりで、問題視されていたのは
一貫して**明るい板**である。

- 撤去対象は `LABEL_BACKGROUND_COLOR = [244, 236, 215, 200]`（クリーム #f4ecd7 を
  **alpha 200** で敷いたベタ矩形）+ padding `[3, 2]`。
- ユーザー要望の言葉は「明るいベタ矩形（背景パネル）が『白枠』として目立ち
  すぎる」。AC #1 も「文字の周囲にベタ矩形が見えない」、AC #3 も「halo が文字
  ごとの白いベタ矩形に見えるほど太くなっていない」。

対して #333 が導入するプレートは、

- **濃色**（ink #3a2712 = app.css の `--ink`）で明暗が逆。
- **alpha 56/255 ≈ 0.22** で、TASK-72 が撤去した alpha 200 の 1/3.6。
- 角丸 + クリーム 1px 縁を持つ「札」で、羊皮紙トーンの地図の凡例枠と同じ語彙。

趣旨を壊さないため、次を実装上の制約として残す。

1. **注記ラベル（都市・河川・山岳・山峰）は一切変えない。** 共通スタイルの
   `background` は `false` のまま、共通 base props の背景クアッドは ADR-0030 の
   不可視値（`LABEL_COLLISION_BACKGROUND_COLOR = [0,0,0,1]`）のまま。プレートを
   持つのは政治ラベル 2 層だけ。
2. **プレートは文字列単位**であって per-character のベタ矩形ではない。deck.gl
   TextLayer の `background` サブレイヤーは文字列 1 件につき 1 枚のクアッドなので、
   TASK-72 AC #3 が嫌った「文字ごとの矩形」には構造的にならない。むしろ #322 の
   太い halo の方が、隣接グリフの halo が繋がって per-character の矩形に
   近づいていた。
3. **明暗の反転をテストで固定する**（プレート色が文字色より暗く、alpha が
   TASK-72 の 200 の 1/3 未満であること）。

## Consequences

- **ADR-0030 の「ほぼ不可視」に例外ができる。** ADR-0030 は衝突参加の全ラベル層に
  alpha 1/255 の背景クアッドを敷くと決めたが、政治ラベル 2 層はそのクアッドの
  **色・余白・角丸を差し替えて可視化する**。ADR-0030 の目的（自己衝突の構造的
  回避）は、クアッドが存在し続ける限り損なわれない。新設したのは見た目だけで、
  描画要素も衝突箱も増えていない。
- **性能への影響は測定済みで無視できる。** #322 相当（`e51a1b1`）と #333 実装
  （`3c36f25`）を個別にビルドして比較した結果、SDF アトラス数は 2 のまま、
  アトラス初回生成 109.0 → 110.6ms（+1.5%）、パン中 fps・フレーム間隔・年代
  切替時間・JS heap はいずれも不変。ただし `tier=top` を独立に調整するため
  TextLayer を 1 枚 → 2 枚に分割したぶん、パン中 draw call が 264.24 → 267.29
  （+3.05 / +1.2%）増えている。フレーム時間は vsync 上限に対して変化せず、
  DPR2 でも GPU 律速に至らない。
- **今後、政治ラベルの視認性を「外縁を太らせる」方向で解こうとしない。** 12px の
  カウンター潰れが上限になるため到達できない。分離量を変えたい場合はプレートの
  alpha・余白・角丸を動かす。
- **参考画像との一致を測るときは測定手法に注意する。** #333 の本番承認時、
  比較画像の中央 1 行から「緑地でだけ沈みが足りない」という残差を検出したが、
  原本 PNG を 13 標本で測り直すと地色による差は −0.006 ± 0.017（t = −0.35）で
  有意差ゼロであり、**残差は計測アーティファクトだった**。プレートの沈み量は
  プレート矩形の行方向で帯平均し、グリフ ink bbox の 4px 手前・プレート端から
  3px 内側までに限って測る（単一行・グレースケール一本化はこの信号量では
  使えない）。詳細は
  `docs/images/issue333-label-reference/README.md` と
  `docs/research/issue-333-label-reference-targets.md` §2.4。
- 規範である参考画像そのものと reference / before / after の比較画像は
  `docs/images/issue333-label-reference/` にコミットしてあり、第三者が完了判定を
  再確認できる（#204 の「根拠がリポジトリから消える」失敗を避けるため）。
