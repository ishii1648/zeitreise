# 都市表示の網羅性と時代別都市名の調査（ユーザー報告）

- 調査日: 2026-08-01
- 契機: ユーザー報告「もっと都市情報を出せないか。ベオグラード・ベルリンを
  一貫して出したい。可能なら時代に応じた都市名（ベオグラード = ハンガリー領期は
  Nándorfehérvár）で表示したい」
- 調査方法: 現行パイプライン（`scripts/build-cities.ts`）と同一ロジックを
  再実装した使い捨てスクリプトで `chandler.csv`（ピン留めコミット）と
  `data/cities.json` を実測。代替データソースは Dataverse API / GitHub API /
  Wikidata SPARQL で一次確認した。実測値は本文に転記済み（スクリプトは
  再生成可能な中間生成物として破棄）。
- 結論の反映先: 未（本レポートを根拠に Issue を起票する想定）

## 1. 結論

1. ベオグラード・ベルリンが年代によって消えるのは表示側の不具合ではなく、
   **上流データ（Chandler）に該当年の人口記録が無い**ことが原因。ベオグラード
   の最古記録は 1433 年、ベルリンは 1600 年で、それ以前は行自体が存在しない。
2. 現行ソースのまま救えるのは「**前後に記録があるのに中間年で消える**」歯抜け
   だけ（172 都市・延べ 735 セル）。対数線形補間を入れれば**この種の欠落は
   ゼロになる**が、ベオグラード 1000〜1400 年・ベルリン 1000〜1530 年は
   片側外挿になるため救えない。ユーザーが挙げた 2 都市はまさにこの型。
3. 代替ソース **Buringh (2021) "European urban population, 700–2000" （DANS,
   CC0-1.0）** は 2,262 都市 × 19 年グリッドが**欠損ゼロ**で、
   ベオグラード・ベルリンとも全スナップショット年に値を持つ。人口下限 5,000 人
   で 1000 年 121 都市 → 1500 年 506 → 1880 年 2,065 と、現行（60 / 158 / 614）
   の 2〜3.4 倍。**「一貫して出す」は構造的に解決する。**
4. ただし Buringh は欧州限定で、現行が表示している**欧州外の大都市 79 件
   （コンスタンティノープル以外のアナトリア・レヴァント・イラン・北アフリカ）
   が丸ごと欠ける**。Chandler を欧州外の補完として併用するハイブリッドが要る。
5. 時代別都市名は既存データでは賄えない。Buringh の別名列は年代情報を持たず
   （`Belgrade → "Singidunum, Belgrad, Belgrado"`、Nándorfehérvár は不在）、
   Wikidata は期間付き公式名を持つが言語別に散逸していて機械抽出に向かない。
   **少数（数十件）の手動キュレーション JSON** が現実的な解。

## 2. 現状の仕組み

`scripts/build-cities.ts` が Chandler の `chandler.csv`（Reba et al. 2016 の
入力 CSV。`fasiha/Historical-Urban-Population-Growth-Data` @ `808ff2b4` に
ピン留め、ADR-0004）を取得し、欧州 bbox（`EUROPE_BBOX` = `[-25, 34, 60, 72]`）
内の行について、各スナップショット年から**過去 50 年・未来 25 年**の窓で
年差最小の記録を選ぶ。窓内に記録が無ければその年はその都市を出さない。

`data/cities.json` の年別件数（現状）:

```
1000:59 1100:44 1200:109 1279:122 1300:129 1400:131 1492:152 1500:157
1530:175 1600:180 1650:180 1700:201 1715:206 1783:306 1800:316 1815:319
1880:609 1900:602 1914:544
```

欧州 bbox 内の候補プールは 682 行・採用ユニーク都市は 633 件。

## 3. なぜ消えるのか（3 つの原因）

Chandler の記録年は都市ごとに飛び飛びで、原因は次の 3 層に分かれる。

### 3.1 窓の外にあるだけ（窓の拡張で救える）

例: **パリ 1100 年**。記録は 1000 年（20,000）と 1150 年（50,000）にあり、 1150
は未来 +50 年で窓（+25）の外。よって 1100 年の地図にパリが出ない。 ベオグラード
1400 年も同型（最古記録 1433 は +33 で窓外）。

窓を広げたときの年別件数（実測）:

| 窓              | 1000 | 1100 | 1200 | 1400 | 1500 | 1700 | 1880 |
| --------------- | ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| -50/+25（現行） | 60   | 44   | 111  | 131  | 158  | 203  | 614  |
| -50/+50         | 62   | 56   | 120  | 139  | 183  | 228  | 616  |
| -100/+50        | 69   | 91   | 127  | 163  | 196  | 237  | 627  |
| -100/+100       | 87   | 134  | 153  | 190  | 220  | 303  | 640  |

増えはするが、窓を広げると急成長期の人口を大きく誤らせる（`FUTURE_WINDOW_YEARS`
を +25 に絞った元々の理由）。**単独では推奨しない。**

### 3.2 前後に記録があるのに中間年で落ちる（補間で救える）

例: **コペンハーゲン**。記録は 1101 → 1400 → 1600 で、1200 / 1279 / 1300 / 1492
/ 1500 / 1530 の 6 年で消える。現行の出現年は `1100,1400,1600,1650,…`
と歯抜けになる。

- 内部ギャップ（初出〜最終の間で消える）を持つ都市: **172 件 / 延べ 735 セル**
- 両側に記録があるので**対数線形補間で 100% 埋まる**（172 → 0 件、735 → 0 セル）
- 追加されるセル数: **+882（現行の総セル 4,572 に対し +19%）**

年別の増加:
`1000:+26 1100:+62 1200:+38 1279:+49 1300:+47 1400:+70 1492:+76
1500:+72 1530:+64 1600:+79 1650:+86 1700:+77 1715:+73 1783:+27 1800:+19
1815:+16 1880:+0 1900:+0 1914:+1`

> **補記（#221 実装時の検証）:** 上記の増分は bbox フィルタ後の生データで
> 測ったもので、パイプラインの既知異常除外（`EXCLUDED_CITY_NAMES` の Gelibolu /
> Qum、`EXCLUDED_RECORDS` の Iznik 1800）を適用していない。
> 除外適用後のパイプライン実測は一部の年で 1〜2 小さい
> （`1000:+26 1100:+61 1200:+38 1279:+47 1300:+45 1400:+68 1492:+75 1500:+71
> 1530:+63 1600:+77 1650:+86 1700:+77 1715:+73 1783:+26 1800:+18 1815:+15
> 1880:+0 1900:+0 1914:+1`、追加セル計
> +867）。差分は全て除外対象由来で、 補間で救える都市の結論（172 件 100%
> 解消）は変わらない。

補間後のベオグラード・ベルリンは**変わらない**（後述 3.3）。救えるのは
コペンハーゲン（1100〜1914 が連続化）、パリ 1100 年、プラハ 1100 年、 ミュンヘン
1400 年など。

### 3.3 上流に記録自体が無い（現行ソースでは救えない）

`chandler.csv` の該当行（全記録）:

```
Belgrade  1433:30000 1456:30000 1500:30000 1600:40000 1632:40000 1700:40000
          1721:30000 1735:30000 1750:30000 1780:30000 1800:26000 1846:17904
          1850:13485 1900:69000 1950:445000 1975:1275000
Berlin    1600:14000 1698:22400 1700:26000 1709:56600 1750:113289 1800:172132
          1825:222000 1850:446000 1875:1045000 1900:2707000 1914:3500000 …
```

Chandler は各時代の世界／欧州上位都市のみを収録しているため、中世の中小都市は
そもそも行に無い。ベオグラード 1000〜1400 年、ベルリン 1000〜1530 年、 ザグレブ
1815 年以前は**片側外挿でしか埋まらず、補間では救えない**。

## 4. 代替データソースの調査

### 4.1 Buringh (2021)（推奨）

- 出典: Eltjo Buringh, "The Population of European Cities from 700 to 2000:
  Social and Economic History", _Research Data Journal for the Humanities and
  Social Sciences_ 6(1), 2021
- データ: DANS Data Station SSH, DOI
  [`10.17026/dans-xzy-u62q`](https://doi.org/10.17026/dans-xzy-u62q)
- **ライセンス: CC0-1.0**（Dataverse API で確認。現行 Reba の CC BY 4.0 より
  制約が緩い。全 6 ファイルが `restricted: false`）
- 形式: `.tab`（TSV, 4.9MB, fileId 20415）/ `.ods` / `.txt` + 解説 PDF 2 本
- 列: `city` / `synonymsandhistoricalnames` / ISO 国コード / `country` / 水系 /
  緯度 / 経度 / 標高 / `year` / `inhabitantsin000-s` / `source` /
  `natureofestimate`

**決定的な性質: 2,262 都市 × 19 年（700, 800, 900, 1000, 1100, 1200, 1300, 1400,
1500, 1550, 1600, 1650, 1700, 1750, 1800, 1850, 1900, 1950, 2000）の
完全グリッドで欠損セルがゼロ**（42,978 行 = 2,262 × 19）。値は
`natureofestimate` 列で `""`（実推定）/ `imputed`（補完）/ `proxied`（代理指標）
に区別されており、推定の質を保持したまま扱える。

本アプリのスナップショット年（1279 / 1492 / 1530 / 1715 / 1783 / 1815 / 1880 /
1914）はグリッドに無いが、両側が必ず埋まっているので補間が常に成立する。

人口下限別の年別都市数（bbox `[-25,34,60,72]`、対数線形補間後の実測）:

| 下限      | 1000 | 1100 | 1200 | 1300 | 1500 | 1600 | 1700 | 1800 | 1880 | 1914 |
| --------- | ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| 3,000 人  | 314  | 457  | 673  | 901  | 992  | 1400 | 1651 | 2061 | 2142 | 2171 |
| 5,000 人  | 121  | 177  | 271  | 428  | 506  | 801  | 919  | 1759 | 2065 | 2105 |
| 10,000 人 | 44   | 56   | 110  | 154  | 205  | 301  | 334  | 644  | 1469 | 1722 |
| （現行）  | 59   | 44   | 109  | 129  | 157  | 180  | 201  | 316  | 609  | 544  |

下限 5,000 人は Bairoch (1988) の元来の収録基準（5,000 人以上）と一致し、 現行の
2〜3.4 倍の密度になる。

ベオグラード・ベルリンは全 19 年で連続する（補間後、単位千人）:

```
Belgrade 1000:7 1100:9 1200:14 1279:19 1300:20 1400:30 1492:30 1500:30
         1530:36 1600:55 1650:30 1700:17 1715:14 1783:6 1800:5 1815:7
         1880:50 1900:100 1914:141
Berlin   1000:1 1100:2 1200:3 1279:4 1300:4 1400:5 1492:9 1500:9 1530:9
         1600:10 1650:23 1700:55 1715:68 1783:149 1800:172 1815:228
         1880:1022 1900:1800 1914:2133
```

ベルリンの 1000〜1300 年（1〜4 千人）は `imputed` で、史実（市壁都市としての
成立は 1230 年代）と照らすと表示には適さない。**人口下限 5,000 人を掛けると
ベルリンは 1400 年以降**になり、史実と整合する。下限は「一貫性」と「史実性」を
同時に満たす調整弁として機能する。

**弱点: 欧州限定。** 現行が表示している都市 633 件を正式名 → 別名 → 座標 15km の
3 段で名寄せした結果:

| 照合           | 件数   |
| -------------- | ------ |
| 正式名一致     | 435    |
| 別名一致       | 76     |
| 座標 15km 一致 | 43     |
| **未マッチ**   | **79** |

未マッチ 79 件はほぼ欧州外（Constantinople は `Istanbul` で収録済みなので該当
しない）:

```
Nishapur, Rayy, Kairouan, Ani, Aleppo, Diyarbakir, Kayseri, Edessa, Antioch,
Fez, Qazvin, Tabriz, Tunis, Konya, Sivas, Tbilisi, Trabzon, Mosul, Qom, Rabat,
Ceuta, Hama, Tlemcen, Bursa, Algiers, Ankara, Smyrna, Tehran, Erzurum, Adana,
Baku, Kutaisi, Tangier, Samarra …（+ Hastings / Pula / Viborg 等の欧州小都市）
```

1000 年の地図でコルドバ・コンスタンティノープル・ニシャプール・カイラワーン
が並ぶ現在の絵は Chandler ならでは。**Buringh 単独への置き換えは退行になる。**

### 4.2 Bairoch, Batou & Chèvre (1988)

- GitHub [`JakeRuss/bairoch-1988`](https://github.com/JakeRuss/bairoch-1988)
  に手入力のデジタル版（`bairoch-1988-tidy.csv`, 652KB）
- **座標を持たない**（列は `country, city, year, population` のみ）ため、
  ADR-0014（出典のない座標合成の禁止）に抵触せず使うには別途の座標付与が要る
- 1100
  年が原典側で欠落、ライセンス表記も曖昧（「著作権は著者に、入力分は自由に」）
- **Buringh が Bairoch の上位互換（拡張・座標付き・CC0）なので採用不要。**

### 4.3 データサイズ

Buringh を下限 5,000 人で採ると延べ 17,646 セル。現行の JSON 形式（年ごとに
name/lon/lat/population を持つ）だと約 1.6MB に膨らむが、都市を一度だけ並べて
年別は index + 人口だけ持つ正規化形式にすれば **約 0.38MB**（現行
`data/cities.json` は 0.53MB）で、**むしろ縮む**。

## 5. 時代別都市名の調査

### 5.1 既存データでは賄えない

- Buringh の `synonymsandhistoricalnames` 列は**年代情報を持たない**フラットな
  別名リスト。`Belgrade → "Singidunum, Belgrad, Belgrado"` で **Nándorfehérvár
  は含まれない**。`Istanbul → "Constantinople, Byzantium,
  Konstantinopel"`、`Koeln → "Cologne, Köln, Colonia Claudia Ara
  Agrippinensium"`
  のように、名寄せには極めて有用だが表示名の年代切替には 使えない。
- 現行の `data/name-ja.json` は英語名 → 日本語のフラットな 1:1 マップで、
  勢力名と共有（ADR-0006）。年の軸が無い。

### 5.2 Wikidata

ベオグラード（Q3711）は `P1448`（official name）に `Nándorfehérvár`（終了時期
1830 年）を持ち、ハンガリー語別名にも `Nándorfehérvár` / `Bolgárfehérvár` /
`Lándorfejérvár` がある。仕組みとしては 存在する。

ただしカバレッジと形式に難がある（SPARQL 実測）:

- 期間 qualifier 付き `P1448` を持つエンティティ: 45,826 件
- うち座標を持ち、終了時期が 1000〜1930 年のもの: 9,071 件
- 実際の中身は 20 世紀の改名が主体（Koper/Capodistria 1954、Kranj/Krainburg
  1918、Mumbai/Bombay 1994）。**開始時期が欠けている**ことが多く、名前は
  **言語別に散逸**する（Bombay が az / ru / bg で別ステートメント）ため、
  「この年のこの都市の呼称」を機械的に一意へ落とせない。

### 5.3 現実的な設計

対象を「**その年代の支配勢力の呼称が英語慣用名と大きく異なり、地図の理解に
効くもの**」に絞れば数十件で収まる。候補: ベオグラード / Nándorfehérvár
（ハンガリー領 1427–1521）、ブラチスラヴァ / Pressburg・Pozsony、 グダンスク /
Danzig、カリーニングラード / Königsberg、ヴロツワフ / Breslau、 リヴィウ /
Lemberg、タリン / Reval、オスロ / Christiania（1624–1925）、 ヘルシンキ /
Helsingfors、サンクトペテルブルク / Petrograd（1914–）など。

データ形式は年区間付きの独立ファイル（例 `data/city-names-historical.json`）:

```jsonc
{
  "Belgrade": [
    {
      "from": 1427,
      "to": 1521,
      "name": "Nándorfehérvár",
      "ja": "ナーンドルフェヘールヴァール",
      "source": "Wikidata Q3711 P1448"
    }
  ]
}
```

表示側は `cityDisplayName(name, ja)`（`src/cities.ts`）を
`cityDisplayName(name, ja, year)` に拡張し、区間に当たれば `ja` を優先する。
`CITY_NAME_JA_OVERRIDES` と同じ「表示層の解決順を 1 か所に集める」設計の延長で、
picking 情報パネルにも同じ関数が効く。既存の `Istanbul → Constantinople`
（`CITY_RENAMES`）は全年代一律の rename なので、この機構に載せ替えると 1930
年の改名という史実に沿った表現になる（本アプリの年代は 1914 までなので
挙動は変わらない）。

## 6. 推奨する進め方

効果と危険度の比で並べた 3 段。それぞれ独立して価値があり、1 → 2 → 3 の順に
段階導入できる。

1. **補間の導入（現行ソースのまま・小）**
   前後に記録がある都市の内部ギャップを対数線形補間で埋める。172 都市 / 735
   セルの歯抜けが消え、延べ +882 セル（+19%）。上流も表示も差し替えないので
   退行リスクが小さく、`docs/data-inventory/` の「補間値」表示の作法（
   `natureofestimate` 相当のフラグ）をここで先に決められる。 ※
   これだけではベオグラード 1000〜1400 年・ベルリン 1000〜1530 年は出ない。
2. **Buringh の併合（中〜大）** Buringh を主ソース、Chandler を欧州外 79
   件の補完とするハイブリッド。 名寄せは正式名 → 別名列 → 座標 15km の 3
   段（実測 87.5% が自動一致）。 人口下限 5,000 人で 1000 年 121 / 1500 年 506 /
   1880 年 2,065 都市。 コストは**日本語表記の追加（最大 2,177 件、現行
   `name-ja.json` は 1,176 キー）**と、JSON
   の正規化フォーマットへの移行。ズーム別の表示制御
   （`visibleCityRankLimit`）は既にあるので画面密度は現行のまま保てる。
3. **時代別都市名（小〜中）** §5.3 の年区間 JSON
   を手動キュレーションし、`cityDisplayName` に年を渡す。 2
   とは独立に実装できる（1 の前でも後でもよい）。

## 7. 再現手順

本調査は使い捨てスクリプトで実測した。再実行する場合:

```fish
# Chandler（現行ソース）
curl -sL "https://raw.githubusercontent.com/fasiha/Historical-Urban-Population-Growth-Data/808ff2b4a279013f58621a3696cb9c28058c6af1/chandler.csv" -o chandler.csv

# Buringh 2021（DANS Dataverse, CC0）
curl -s "https://ssh.datastations.nl/api/datasets/:persistentId/?persistentId=doi:10.17026/dans-xzy-u62q"  # ファイル一覧・ライセンス
curl -sL "https://ssh.datastations.nl/api/access/datafile/20415" -o buringh.tab
```

Chandler 側は `scripts/build-cities.ts` の `parseChandlerCsv` /
`pickNearestRecord` / `filterCitiesToBbox` をそのまま import すれば同じ選定を
再現できる。Buringh 側は緯度経度が**カンマ小数点**（`"44,83"`）である点、
人口が**千人単位**である点に注意。
