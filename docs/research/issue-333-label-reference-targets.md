## 0. 結論の要約

**参考画像の政治ラベルは「細い濃色外縁 + 文字列単位の濃色プレート」であり、 #267
/ #308 / #322 が積み上げてきた「太い SDF halo だけ」とは別の構成だった。**

| 要素           | 参考画像                                                 | #322 本番相当                            |
| -------------- | -------------------------------------------------------- | ---------------------------------------- |
| 文字           | 純白                                                     | クリーム #f8f2e2                         |
| 濃色外縁       | **1.0〜1.5 CSS px**（サイズによらずほぼ一定）            | 12px で 1.69 / 18px で 2.53 CSS px       |
| 文字列の下支え | **角丸の濃色プレート**（alpha ≈ 0.22 + クリーム 1px 縁） | **無し**（alpha 1 の不可視クアッドのみ） |

つまり #322 は「参考画像の 1.5〜1.8 倍の太さの外縁」で「参考画像には有る
プレート」の役目まで負わせようとしていた。外縁だけで地色から分離しようとすると
12px ラベルのカウンターが潰れる（#322 が実測した `outlineWidth` 13〜14 の上限）
ため、そもそも到達できない構成だった。#322 が不採用理由に挙げた「暗い板」は、
**参考画像そのものの主要素**である。

## 1. TASK-72 の「見える背景パネル禁止」との関係（判定）

### 判定: 現行の制約を維持したままでは参考画像に到達できない。制約の趣旨は壊さずに解く。

TASK-72（`docs/archive/backlog-tasks/task-72 - 地図ラベルの背景パネル（白枠）を撤去し白-halo-を実効化する.md`）
の記録を読むと、禁止されたものと、その理由は次のとおり:

- 撤去対象は `LABEL_BACKGROUND_COLOR = [244, 236, 215, 200]`（クリーム #f4ecd7
  を **alpha 200** で敷いたベタ矩形）+ padding `[3, 2]`。
- ユーザー要望の言葉は「**明るいベタ矩形（背景パネル）が『白枠』として
  目立ちすぎる**」。AC #1 も「文字の周囲にベタ矩形が見えない」、AC #3 も 「halo
  が文字ごとの白いベタ矩形に見えるほど太くなっていない」で、
  **問題視されていたのは一貫して「明るい板」**である。
- 対象は国名・HRE 領邦名・都市名・河川名の**全 TextLayer**（当時は
  `labelLayerBaseProps` が 1 つだった）。

一方 #333 が規範とする参考画像のプレートは、

- **濃色**（ink #3a2712）で、明暗が逆。
- **alpha ≈ 0.22（56/255）**で、TASK-72 が撤去した alpha 200 の 1/3.6。
- 角丸 + クリーム 1px 縁を持つ「札」で、羊皮紙トーンの地図の凡例枠と同じ語彙。

したがって **TASK-72 の禁止の趣旨（明るい板で地図を分断しない）は保ったまま、
参考画像のプレートを入れられる**。加えて Issue #333 の修正方針 3 が 「TASK-72
の『見える背景パネル禁止』は注記ラベル全体の過去要件であり、本件の
政治ラベル完成見本より優先する前提にしない」と明示している。

趣旨を壊さないために、次を実装上の制約として残した。

1. **注記ラベル（都市・河川・山岳・山峰）は一切変えない。** 共通スタイル
   `labelTextStyleProps().background` は `false` のまま、共通 base props
   （`labelLayerBaseProps`）の背景クアッドは TASK-143 の不可視値
   （`LABEL_COLLISION_BACKGROUND_COLOR = [0,0,0,1]`）のまま。プレートを持つのは
   政治ラベル 2 層だけ（テスト「注記ラベル（都市・河川・山岳・山峰）は
   不可視クアッドのまま（#333 AC9）」で固定）。
2. **プレートは文字列単位**であって per-character のベタ矩形ではない。 deck.gl
   TextLayer の `background` サブレイヤーは文字列 1 件につき 1 枚の
   クアッドなので、TASK-72 AC #3 が嫌った「文字ごとの矩形」には構造的に
   ならない。むしろ #322 の太い halo の方が、隣接グリフの halo が繋がって
   per-character の矩形に近づいていた（`cmp-labels-x4.png` の中段）。
3. **明暗の反転をテストで固定**する（`POLITICAL_LABEL_PLATE_COLOR` が
   文字色より暗く、alpha が TASK-72 の 200 の 1/3 未満であること）。

### 旧構成に「戻す」わけではない

TASK-143 以降、**衝突参加の全ラベル層はすでに `background: true`** である
（`labelCollisionBackgroundProps`）。アンカー画素がグリフの空白に落ちるラベル
（「ライン川」「ローマ」「ボヘミア王国」など 11 件）が自己衝突判定に失敗して
永久に描画されない問題への対策で、alpha 1 の不可視クアッドを敷いている。 #333
がやったのは**この既存のクアッドの色・余白・角丸を政治ラベル層だけ
差し替えた**ことであり、描画要素も衝突箱の存在も新設していない。

## 2. 参考画像の測定（AC2 の目標値）

参考画像から 5 つのラベル（神聖ローマ帝国・フランス王国・ノルマンディー公領・
ブルゴーニュ・ポーランド）を測った。手順と生の数値は次のとおり。

### 2.1 フォントサイズ（CJK の送り幅から逆算）

日本語グリフは等幅送りなので、`インク幅 / 文字数 ≈ フォントサイズ`。

| ラベル             | 文字数 | インク幅（px） | 推定サイズ |
| ------------------ | ------ | -------------- | ---------- |
| 神聖ローマ帝国     | 7      | 139            | ≈ 20px     |
| フランス王国       | 6      | 98             | ≈ 16.3px   |
| ポーランド         | 5      | 77             | ≈ 15.4px   |
| ノルマンディー公領 | 9      | 138            | ≈ 15.3px   |
| ブルゴーニュ       | 6      | 90             | ≈ 15.0px   |

上位国名（神聖ローマ帝国）と構成勢力（ノルマンディー公領）の比は約 1.3。
本アプリの階層別サイズ（top 18/16px・constituent 14px・sub 12px。#267 / #228
で決定済み）はこの比のレンジに収まっており、**サイズ階層は #333 の
変更対象ではない**（Issue のスコープ外）。

### 2.2 文字色

グリフのインク部分（輝度 245 以上）8140 画素中 713 画素の分布は、最頻値が
`(255, 255, 255)`（366 画素）、平均 `(253.7, 253.8, 251.9)`。**参考画像の
文字は純白**。

実装は `POLITICAL_LABEL_COLOR = #f8f2e2` を**据え置いた**。理由は、強調
（ホバー/クリック）時の `ACTIVE_POLITICAL_LABEL_COLOR = 純白` との差を残す
必要があるため（TASK-93 の強調フィードバック）。#f8f2e2 と純白の差は 14〜18px
の日本語グリフでは視認できず、Issue の期待挙動「白〜明るいクリーム
の…文字」の範囲内。

### 2.3 濃色外縁（グリフの縁）

グリフの縦画を横断する走査（例: y=606, x=951..965 で
`185 255 163 26 76 111 …`）から、**濃色の芯 1px + 前後 1px
のアンチエイリアス**、 すなわち実効 **1.0〜1.5 CSS px**。フォントサイズが 1.3
倍違う 2 ラベルで 絶対幅がほぼ変わらないのが特徴（20px の字で 1.3px、15.3px
の字で 1.2px）。

色は輝度 35 未満の画素の平均が `(32.1, 26.9, 15.6)`、最頻値クラスタは
`(34, 34, 17)` 付近。実装の
`POLITICAL_LABEL_HALO_COLOR = #3a2712 =
(58, 39, 18)`
よりやや暗いが、**据え置いた**: app.css の `--ink` と同値である
ことが「境界もラベルの輪郭も同じインクで引いた古地図」という既存の設計不変条件
（#267）で、1px 幅での色差は視認できないため。

### 2.4 下支えプレート

`inside = α·C + (1-α)·outside` を C = #3a2712 として解いた（プレート内側の
文字が無い余白部と、同一領土色の外側とを比べる）。

| ラベル（領土色）               | inside                | outside               | α（R/G/B）            |
| ------------------------------ | --------------------- | --------------------- | --------------------- |
| 神聖ローマ帝国（苔緑・左余白） | (136.0, 142.0, 106.8) | (157.9, 168.7, 135.2) | 0.219 / 0.206 / 0.242 |
| ポーランド（淡橙・左余白）     | (174.2, 149.6, 114.0) | (201.8, 177.2, 145.0) | 0.192 / 0.200 / 0.244 |

**明るい領土色でも暗い領土色でも同じ α** に落ちるので、乗算ブレンドではなく 一定
alpha の濃色オーバーレイ。採用値は **56/255 ≈ 0.22**。

プレート外周には**明色の帯**があり（神聖ローマ帝国の左縁: x=901 で (185.0,
193.6, 155.3)、x=902 で (175.9, 183.1, 144.5)、外側は (155.9, 167.3,
130.4)）、クリーム #f4ecd7 に対する比率は 0.33 と 0.22、 合計 ≈ 0.55 px·α。**1px
× alpha 128（0.50）** とほぼ一致するのでこれを採る。

寸法（神聖ローマ帝国、フォント ≈ 20px）:

| 項目         | 実測                                           | 正規化                 |
| ------------ | ---------------------------------------------- | ---------------------- |
| プレート矩形 | x 901..1051 / y 591..622（151 x 32px）         | 高さ = 1.60 × フォント |
| 左右余白     | (151 − 送り 140) / 2 ≈ 5.5px                   | 0.275 em               |
| 上下余白     | (32 − 20) / 2 = 6px                            | 0.30 em                |
| 角丸         | 左上隅の追跡（(905,591) → (901,597)）で 5〜6px | 0.28 em                |

## 3. 採用方式

### 3.1 プレートは TextLayer の `background` サブレイヤー（候補の比較）

| 候補                                              | 採否   | 理由                                                                                                                                                                                             |
| ------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **A. TextLayer の `background` を可視化**         | 採用   | 既に TASK-143 で `background: true` の不可視クアッドが敷かれており、色・余白・角丸を変えるだけ。data / anchor / size / 衝突 extension / priority を文字側と共有するため AC8 が構造的に満たされる |
| B. プレート専用の PolygonLayer / IconLayer を追加 | 不採用 | 文字列の実寸（グリフの送り幅の合計）を自前で測る必要があり、フォント差で必ずずれる。衝突判定も別レイヤーになり #322 の候補B と同じ「片層だけ間引かれる」罠に落ちる                               |
| C. shader extension でグリフに影を足す            | 不採用 | 参考画像の下支えは**文字列単位**の矩形で、グリフ単位の影では再現できない（per-character のベタ矩形は TASK-72 が明確に禁じた見た目でもある）                                                      |

deck.gl 9.3.7 の `TextBackgroundLayer` は `borderRadius` / `padding` /
`getFillColor` / `getLineColor` / `getLineWidth` を持ち、角丸 + 縁 + 余白の
すべてを賄える（`@deck.gl/layers/src/text-layer/text-background-layer/`）。
`TextLayer` からは `backgroundBorderRadius` / `backgroundPadding` /
`getBackgroundColor` / `getBorderColor` / `getBorderWidth` として渡す。

### 3.2 階層別スタイルは TextLayer の分割で持つ（AC3）

`outlineWidth` / `backgroundPadding` / `backgroundBorderRadius` は deck.gl の
**レイヤー単位 props で accessor にできない**。よって `tier = top` に
constituent / sub と別の値を持たせるにはレイヤーを分けるしかない。

`LABEL_LAYER_ID = "power-labels"`（constituent / sub）と
`TOP_LABEL_LAYER_ID = "power-labels-top"`（top）の 2 枚にし、
`filterPoliticalLabelsByGroup` が datum を排他的に振り分ける。

**#322 が棄却した候補B（二重 TextLayer）とは別物**である点が要点:

|                             | #322 候補B                                         | #333 の階層分割                                             |
| --------------------------- | -------------------------------------------------- | ----------------------------------------------------------- |
| 同一 datum が何層に現れるか | 2 層（下層 = 影・上層 = 文字）                     | **1 層だけ**                                                |
| 自己衝突                    | 同一アンカーで互いに衝突し、片方が消える           | 起きない（同じアンカーの datum が 2 つ無い）                |
| 字送りのずれ                | 下層のサイズを変えるとグリフ位置がずれ二重像になる | 起きない（1 つの datum は 1 つの getSize でしか描かれない） |
| フォントアトラス            | 2 層とも同じ設定なので共有                         | 同左（`POLITICAL_LABEL_FONT_SETTINGS` を両層が参照）        |

### 3.3 実装値

`labelHaloWidthPx(outlineWidth, size, POLITICAL_LABEL_FONT_SETTINGS)` は
`0.75 * outlineWidth * size / 64` なので、目標 em から逆算する。

| グループ | tier / level      | サイズ | outlineWidth | 実効外縁 | 参考画像の対応値    |
| -------- | ----------------- | ------ | ------------ | -------- | ------------------- |
| top      | top / overview    | 18px   | 6            | 1.27 px  | 1.3 px（20px の字） |
| top      | top / mid・detail | 16px   | 6            | 1.13 px  | 1.04 px 相当        |
| lower    | constituent       | 14px   | 7            | 1.15 px  | 1.10 px 相当        |
| lower    | sub               | 12px   | 7            | 0.98 px  | 0.94 px 相当        |

**lower の `outlineWidth` の方が大きい**のは参考画像の性質どおり（外縁の
絶対幅がほぼ一定 = 小さい字ほどサイズ比では太い）。deck.gl の実効 halo は
サイズ比例なので、単一の `outlineWidth` では両立しない。これが AC3 「top を
constituent / sub と独立して調整できる構造」が必要な実際の理由である。

プレート:

| グループ | padding（px） | 角丸（px） | プレート高 / フォント      |
| -------- | ------------- | ---------- | -------------------------- |
| top      | 5             | 5          | 28/18 = 1.56、26/16 = 1.63 |
| lower    | 4             | 4          | 22/14 = 1.57、20/12 = 1.67 |

参考画像の 1.60 / 0.275 em / 0.28 em に対して ±0.07 の範囲。 `backgroundPadding`
と `backgroundBorderRadius` は CSS px 固定（getSize に
比例しない）ので、グループの代表サイズで丸めた整数にしている。

これら 4 種の実寸は `politicalLabelRenderSpecTable()` が返す固定標本として
`src/labels_test.ts` にリテラルで固定してある（AC12）。

### 3.4 実描画での検証（after の再測定）

同じ測定手順を after のスクリーンショット（1600x757 / DPR 1、1100 年 z5、
本番タイル）へ適用した。

- 神聖ローマ帝国（top / 16px）のプレート: y 300..326 = **27px**（設計 26px
  - アンチエイリアス 1px）。左縁の画素は `(191.8)` で、クリーム alpha 0.5 を
    地色 151.5 に重ねた計算値 191.6 と一致。
- プレート内側 126.9 / 外側 151.5 → **α = 0.217**（参考画像 0.20〜0.24）。
- ノルマンディー公領（lower / 14px）のプレート高: y 381..403 = **22px**
  （設計どおり）。

## 4. コスト実測（AC10）

`dist/index.html` に使い捨ての計測スクリプトを注入（`document.createElement`
を包んで 256px 以上の canvas を記録 / `PerformanceObserver` の `longtask` を
積む / `requestAnimationFrame` の間隔を採る）して、同一手順で 3 回ずつ測った
（1600x900 / DPR 1、1100 年 z5 → 1300 年へ切替）。

| 指標                                       | before（#322 本番相当）                   | after（#333）                           |
| ------------------------------------------ | ----------------------------------------- | --------------------------------------- |
| フォントアトラス canvas                    | 1024x1024 × 2 枚（共通 + 政治ラベル専用） | **同じ 2 枚**（階層分割しても増えない） |
| 1300 年へ切替後のアトラス                  | 1024x1024 + 1024x2048                     | 同じ                                    |
| canvas 由来のメモリ（アトラス + deck/map） | 17.24 MB → 21.24 MB                       | 同じ                                    |
| 初回ロードの long task 合計                | 223 / 164 / 168 ms                        | 224 / 164 / 169 ms                      |
| 定常フレーム間隔（中央値 / p90）           | 16.7 / 16.7 ms                            | 16.7 / 16.7 ms                          |

アトラスが増えないのは、フォントアトラスのキャッシュキーが fontFamily /
fontWeight / fontSize / buffer / radius / cutoff で （`font-atlas-manager.ts`
`_getKey`）**`outlineWidth` を含まない**ため。 2 層は同じ
`POLITICAL_LABEL_FONT_SETTINGS` を参照し、`characterSet` も 同じ（絞り込み前の全
datum 由来）配列参照を渡すので、モジュールスコープの LRU
キャッシュがそのままヒットする。

TextLayer が 1 枚増えることによる描画呼び出しの増加は、**同じ datum 集合を 2
つに分けただけ**なのでインスタンス総数は不変（long task・フレーム間隔に
差が出ていないのはこのため）。

### 衝突箱への影響

`backgroundPadding` は衝突判定パスでも加算される（`collisionTestProps` の
`sizeScale` はグリフ矩形にしか掛からず padding には掛からない）。14px・ 6
文字のラベルなら衝突箱は `2.8 × 84 = 235px` 幅・`2.8 × 14 = 39px` 高で、 padding
が足すのは幅 +8px（+3%）・高さ +8px（+21%）。z4〜z7 の各年代の before / after
比較（`cmp-*.jpg`）では表示ラベルの取捨に目立った差は出て いない。

## 5. 変えなかったもの

- 都市・河川・山岳・山峰の共通クリーム halo（`LABEL_OUTLINE_WIDTH = 5` /
  `LABEL_OUTLINE_COLOR` / `LABEL_FONT_SETTINGS`）と、それらの不可視衝突
  クアッド（TASK-143）は不変（AC9）。
- 政治ラベル専用の SDF 設定 `POLITICAL_LABEL_FONT_SETTINGS`（#322 の radius 24 /
  smoothing 0.05 / buffer 11）は不変。`outlineWidth` を 12 から 6〜7
  へ下げたので上限には一層余裕がある。
- サイズ階層（#228 / #267）・衝突優先度の帯（`tieredLabelPriority`）・
  ズーム段の表示制御（`filterPowerLabelsByZoom`）・polylabel アンカー・
  強調時の文字色（TASK-93）は不変（#333 スコープ外）。
