# 年代別の勢力説明（`data/power-descriptions.json`）

Issue #283 で導入した年代別の**一文要約**の台帳。Issue #423 でクリック説明
パネルと実行時の取得・参照は撤去した。データ自体は説明機能を将来再設計するときの
開発者向け記録として保持し、現在のクライアントは取得・保持・表示しない。

## 1. 位置づけ

- **データの性質**: 上流データセットの複製ではなく、**本リポジトリで執筆した
  テキスト**。したがって `scripts/build-attribution.ts` の
  `UNATTRIBUTED_DATA_FILES` に載せてあり、出典 metadata は持たない （feature
  も座標も持たず、pick の対象にならない）。
- **生成されない**: ビルドスクリプトで再生成しない手書きデータ。編集は
  `data/power-descriptions.json` を直接直す。
- **検証**: `scripts/power-descriptions-json_test.ts` が形式・年代・重複・
  文長・キーの実在（後述）を CI で固定する。

## 2. スキーマ

```jsonc
{
  "note": "…（人間向けの注記。実行時には読まれない）",
  "descriptions": [
    {
      "name": "Poland-Lithuania", // 補正後の内部名（英語 NAME）
      "years": [1492, 1500, 1530], // data/index.json のスナップショット年
      "text": "…時代です。" //   一文要約（句点 1 個で終わる）
    }
  ]
}
```

### 旧実装のキー解決順（Issue #423 で撤去）

表示名（日本語）ではなく**補正後の内部名**をキーにする。`data/name-ja.json` の
訳語を変えただけで紐付けが壊れるのを避けるためで、既存のラベル整形
（`src/info.ts`
`displayLabel`）・色割当（`scripts/build-colors.ts`）と同じ順序に そろえてある。

1. クリックされた feature の `NAME`（生値）
2. `data/name-overrides.json` の `renames` で正規化（綴りゆれの吸収。 例:
   `Castille` → `Castile`）
3. 正規化後の内部名 × **現在の表示年**で本ファイルを引く
4. 日本語表記（`name-ja.json`）は**パネル 1 行目の表示だけ**に使い、照合には
   使わない

引けなかった場合は `null` を返し、パネルは説明欄（区切り線ごと）を畳んで名称 +
年代だけになる。**別年代の説明で埋め合わせることはしない**（Issue #283 AC8）。

対象は政治勢力レイヤー（base 勢力 + 領邦・主権政体オーバーレイ）に限る。
河川・都市・山脈・山峰は年代別の勢力説明を持たず、名称（+ 標高 / 人口）だけの
従来表示のままで、年代も表示しない（年代を添えると「年代で内容が変わる」という
誤った含意が生まれるため）。

## 3. 執筆方針（重要）

- **定説として確立した範囲の一般的な characterization に限る。** 具体的な年号・
  数値・人名の逸話など、確認できない断定的細部は書かない。迷ったら**書かず**、
  フォールバック（名称 + 年代のみ）に任せる。
- **一文・句点 1 個で終える。** 長さの上限はコードポイント 68 字 （`.info-panel`
  の内容幅 ≈ 284px ÷ 12px 和文 ≈ 23 字/行 × 3 行）。現状の最長は 44
  字で、320×568 の実測でも最大 3 行に収まる（§5）。
- **語り口を揃える。** 「〜時代です。」で結ぶ。勢力名そのものは 1 行目に出るので
  文中で繰り返さない（1 行目と重複するため）。
- **上流データの区切りに従う。** スナップショット年の間の出来事は「その年の
  状況」として書き、年をまたぐ物語にしない。

### どこで止めたか、なぜか

- **止めた線**: 「ヨーロッパ政治史の概説で必ず言及される規模の勢力」まで。中小の
  領邦・都市国家（Fivizzano・Pontremoli・Massa・Lucca 等）、ヨーロッパ域外の
  勢力（Ghaznavid Emirate・Timurid Empire・central Asian khanates 等）、上流の
  データが分類名で置いた集合（`Celtic kingdoms`・`Finno-Ugric taiga
  hunter-gatherers`・`Other Rus Principalities`
  等）は**登録していない**。
- **理由**: これらは §3 の「定説として確立した一般的な
  characterization」を一文で
  書ける確度が低い（学説が割れる・そもそも一つの政体ではない・上流の面が実体を
  どこまで反映しているか不明）。誤った断定を出すより、フォールバックで名称 +
  年代だけを出す方が正しい（AC8 が未登録を許容しているのはこのため）。
- **1800 年が最も薄い（11 件 / 55 種）**のは、上流データが同年の帝国域を多数の
  小領邦へ分解しており、主要勢力の割合が下がるため。神聖ローマ帝国の名前が 1783
  / 1800 の `NAME` に現れない（個々の領邦に分かれている）ことも効いている。

### 追加するときの手順

1. `data/power-descriptions.json` にエントリを足す（§3 の方針を守る）
2. `deno test scripts/power-descriptions-json_test.ts`
   で形式・年代・キーの実在・
   文長を確認する（キーがその年の実データに無ければ落ちる）
3. 根拠となる参考の系統を §6 の表に足す

## 6. 根拠・参考

個々の文は特定の文献の記述の要約ではなく、**複数の概説が一致して述べる範囲**の
一般的な特徴づけに限っている（§3）。そのため文ごとの出典注記は付けず、依拠した
参考の系統をここに記す。

| 範囲                             | 依拠した参考の系統                                                                                                                  |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| ヨーロッパ通史（全年代）         | 大学教養レベルのヨーロッパ史概説（各国史・時代区分の標準的記述）で一致している事項のみを採る                                        |
| 各勢力の版図・体制の推移         | 本リポジトリが描画している上流データ（`docs/data-inventory/README.md` §1 の各データセット）そのものが示す領域の変化と矛盾しないこと |
| 年代ごとの「その年に何が焦点か」 | スナップショット年の選定根拠（`docs/app-spec.md` の年代設計）に合わせ、その年に区切って語れる範囲に限る                             |

**この台帳が担保するのは「書いていないこと」でもある**: 具体的な年号・戦役名・
条約名・人名・人口や面積の数値は、確度を担保できないため意図的に書いていない。
それらを知りたい利用者の導線は、ⓘ（出典）から上流データセットへ辿る経路である。
